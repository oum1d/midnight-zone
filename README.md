# ЗОНА ПОЛУНОЧИ · STREFA PÓŁNOCY · THE MIDNIGHT ZONE

Промо-сайт передвижной научно-популярной выставки о глубоководье.
Главная страница — вертикальное погружение: скролл работает как спуск,
фон непрерывно темнеет, счётчик слева отсчитывает метры. На дне ждёт
единственная кнопка «Купить билет».

Три языка: польский, русский, английский.

---

## Как запустить

**Просто открыть.** Двойной клик по `index.html` — сайт полностью работает
по протоколу `file://`, без сервера, сборщика и интернета (без сети
подставятся системные шрифты, всё остальное на месте).

**Важно:** открывать нужно в настоящем браузере — правый клик по `index.html`
→ «Открыть с помощью» → Chrome. Встроенные просмотрщики файлов показывают
локальный HTML снимком и не подгружают соседние файлы: сайт выглядит как
голая разметка, хотя с ним всё в порядке.

**С локальным сервером** — если нужен адрес `http://`, чтобы проверить
`sitemap.xml`, `robots.txt`, страницу 404 или заголовки безопасности:

```bash
powershell -ExecutionPolicy Bypass -File serve.ps1
```

Дальше `http://localhost:8123/`. Остановка — Ctrl+C.

Сборки нет: собирать нечего. Ни Node, ни npm, ни зависимостей.

### Изображения залов

Выставка вымышленная, фотографий её залов не существует, поэтому изображения
залов генерируются. Чтобы двенадцать кадров выглядели как съёмка одного
аквариума, а не как двенадцать разных картинок, работают три вещи:

1. **Общий хвост промпта** (`tools/photos.json` → `style`) описывает одно
   здание и одну камеру: чёрные матовые стены, тёмный полированный бетонный пол,
   циановые LED-линии в потолке, изогнутые акриловые стёкла, объектив 24 мм,
   шум высокого ISO. Меняется только сцена — экспонат зала.
2. **Референс.** Если генератор принимает картинку-образец, залы 2–12 делаются
   по образцу зала 1 — порядок расписан в `tools/hall-prompts.md`.
3. **Общая цветокоррекция** поверх генерации (`grade`): частичная тонировка
   в холодную гамму глубины, контраст и виньетка. `mix` 0.55 держит серию в одной
   гамме, но оставляет свет и материалы живыми — кадр выглядит как фото,
   а не как постер.

Кадры кладутся в `tools/photos-raw/` под именами залов (`edge.png`,
`pressure.jpg` …, подходят JPEG и PNG) и обрабатываются:

```bash
powershell -ExecutionPolicy Bypass -File tools\prepare-photos.ps1
```

Скрипт режет кадры в 4:3, делает два размера (600×450 и 1200×900), сам
отмечает в `exhibition.js`, что изображения сгенерированы, и пишет `CREDITS.md`.
Под сеткой залов на сайте тогда появляется прямая пометка: это визуализация,
а не фотографии выставки. Если какого-то кадра нет, в карточке остаётся
заглушка с номером зала.

Кадры генерирует `tools/generate-halls.ps1`: модель FLUX.1 [schnell]
(Black Forest Labs, лицензия Apache 2.0 — можно и в коммерческом проекте)
через [AI Horde](https://aihorde.net) — бесплатную сеть видеокарт добровольцев.
Регистрация и оплата не нужны. Без ключа запрос стоит в общей очереди
5–10 минут, поэтому скрипт отправляет несколько залов сразу и забирает
кадры по мере готовности. Залы, у которых кадр уже есть, пропускаются —
прерванный запуск можно просто повторить.

Неудачный зал перегенерируется отдельно, с несколькими вариантами на выбор:

```bash
powershell -ExecutionPolicy Bypass -File tools\generate-halls.ps1 -Only voices -Variants 3
```

Варианты ложатся в `tools/photos-raw/variants/`, выбранный переименовывается
в `tools/photos-raw/<зал>.png`. Бесплатный ключ AI Horde даёт приоритет
в очереди; его передают только через переменную окружения `AI_HORDE_KEY`
(см. `.env.example`), в файлы проекта он не записывается.

Чтобы залы не стояли пустыми, пока идёт очередь, `tools/draft-halls.ps1`
за несколько минут делает черновики через Pollinations (модель слабее)
в `tools/photos-raw/draft/`. `prepare-photos.ps1` берёт черновик только
для зала без чистового кадра и пишет в отчёте `draft: <зал>`; когда чистовой
придёт, достаточно запустить `prepare-photos.ps1` ещё раз.

### Существа в фоне погружения

Шесть видов — рыба, медуза, морской конёк, скат-манта, осьминог и краб —
расставлены по спуску тринадцатью существами разного размера. Все они
линейные иллюстрации в PNG с одним цветом и одним свечением через CSS.

Исходные иллюстрации — 2048×2048 на белом фоне, по 200–400 КБ. В сайт они
попадают через `tools/prepare-creatures.ps1`: скрипт переводит белый фон
в прозрачность, срезает запечённый ореол, перекрашивает линии в циан
`#5FF2E4`, обрезает поля и уменьшает до 520 px. Шесть картинок весят вместе
166 КБ вместо 1,75 МБ.

Заменить или добавить существо:

```bash
powershell -ExecutionPolicy Bypass -File tools\prepare-creatures.ps1 -Source "папка\с\иллюстрациями"
```

Скрипт узнаёт животное по имени файла (`*jellyfish*`, `*seahorse*`, `*manta*`,
`*crab*`, `*octopus*`, `*deep-sea_fish*`). Новое существо нужно дописать в
список `$map` в скрипте, а затем в `IMAGES` и `CREATURES` в `assets/js/dive.js`
— там же задаются глубина, место на экране и размер.

Картинки грузятся не сразу, а когда до существа остаётся меньше 1600 метров
погружения: на первом экране скачиваются только ближайшие к поверхности.

### Почему данные в `.js`, а не в `.json`

Сайт должен открываться двойным кликом. По протоколу `file://` браузер
запрещает `fetch()` локальных файлов — JSON просто не загрузится. Обычный
`<script>` этим ограничением не задет, поэтому данные лежат в глобальной
переменной. Структура ровно та же, что была бы в JSON: при переезде на
сервер замена делается в одном месте.

### Как устроены три языка

В разметке стоят только ключи:

```html
<h1 data-i18n="halls.h1"></h1>
<input data-i18n-attr="placeholder:forms.namePh">
```

Язык определяется в порядке: `?lang=` в адресе → сохранённый выбор →
язык браузера (украинский ведёт на русский) → польский. Переключение
происходит без перезагрузки; динамические блоки слушают событие `mz:lang`
и перерисовывают себя.

## Что нужно заменить перед реальным запуском

Всё демонстрационное помечено прямо на страницах, но списком:

1. **Домен.** Сейчас везде `https://oum1d.github.io/midnight-zone` — в `canonical`,
   `hreflang`, Open Graph, `sitemap.xml`, `robots.txt`. Замена — поиск и
   замена по строке.
2. **Даты, адрес, телефон, почта** — `assets/data/exhibition.js` (`meta`)
   и блоки `visit` в трёх словарях.
3. **Изображения залов** — сгенерированная визуализация, это сказано на сайте.
   Когда появится съёмка самой выставки: положить кадры в `tools/photos-raw/`
   под именами залов (`edge.jpg` … `unknown.jpg`) и запустить
   `tools/prepare-photos.ps1`. Цветокоррекция останется той же.
4. **Материалы для учителя** — сейчас строки-заглушки без ссылок. Ссылки
   в никуда не поставлены намеренно: человек нажмёт и получит ошибку.
5. **Загруженность календаря.** Считается хешем от даты — один и тот же день
   всегда выглядит одинаково, но это выдумка. При реальном запуске
   `occupancy()` и `seatsFor()` в `assets/js/tickets.js` заменяются
   на данные из системы продаж.
6. **Переводы.** Польский и английский написаны заново в той же интонации,
   что и русский, а не переведены дословно. Перед показом клиенту их стоит
   дать на вычитку носителю.
7. **`og-image.png`** — сгенерирован скриптом, годится как временный.
   Для реального запуска лучше нарисовать вручную.
8. **Политика конфиденциальности** — шаблон, а не юридический документ.
   Это написано и на самой странице. Состав данных, сроки хранения и
   реквизиты администратора должен проверить юрист.

## Что нужно подключить, чтобы формы заработали

Сейчас три формы (покупка, заявка школы, вопрос) проверяют данные,
показывают понятные ошибки и выводят честное сообщение: «в рабочей версии
это ушло бы туда-то, здесь не отправлено никуда». Бэкенда нет, и сайт этого
не скрывает.

Чтобы формы заработали по-настоящему, нужно:

1. **Эндпоинт приёма заявок** — свой сервер, serverless-функция или сервис
   форм. В `assets/js/forms.js` заменить вызов `showSuccess()` на `fetch()`
   к этому адресу.
2. **Серверную валидацию.** Продублировать все проверки на сервере.
   Клиентская валидация — это удобство, а не защита: её обходят за минуту.
3. **CSRF-токен** и **ограничение по IP**. Ограничение частоты на клиенте
   (30 секунд) отсеивает только случайные повторные нажатия.
4. **Почту или CRM** — куда заявка попадает дальше.
5. **Оплату** — если появится. Карточные данные на своей стороне не хранить
   и не собирать: только официальный checkout платёжного провайдера.

Переменных окружения сейчас нет, поэтому нет и `.env.example`: хранить
нечего. Когда появится бэкенд, ключи держать в панели хостинга, а не в
репозитории.

## Безопасность

Что сделано на стороне сайта:

- Весь текст вставляется через `textContent`. `innerHTML` используется
  ровно в одном месте — для собственных SVG-силуэтов, то есть никогда
  для данных, которые могут прийти извне.
- Honeypot-поле в каждой форме: невидимое человеку, заполняется ботами.
- Ограничение частоты отправки.
- Обязательное согласие на обработку данных у каждой формы.
- Никаких сторонних скриптов, счётчиков и аналитики. Шрифты лежат в
  проекте (`assets/fonts/`, SIL OFL 1.1). Наружу уходит один запрос —
  плитки карты OpenStreetMap на странице «Как добраться», и только когда
  человек долистал до карты. Cookie сайт не ставит вообще; в локальном
  хранилище лежит только выбранный язык.
- Внешних ссылок нет; если появятся — `rel="noopener noreferrer"`.
- Никаких ключей, токенов и приватных адресов в коде.

### Заголовки для продакшена

Метатегом CSP не ставится намеренно: на протоколе `file://` источник `'self'`
не совпадает ни с чем, и сайт перестал бы открываться двойным кликом — а это
одно из условий проекта. Правильное место для CSP — заголовки сервера.
`serve.ps1` их уже отдаёт, оттуда же можно скопировать.

Nginx:

```nginx
add_header Content-Security-Policy "default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; font-src 'self'; img-src 'self' data: https://tile.openstreetmap.org; connect-src 'self'; object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'" always;
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
add_header X-Content-Type-Options "nosniff" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
add_header Permissions-Policy "geolocation=(), camera=(), microphone=(), payment=()" always;
```

Netlify — файл `_headers` в корне:

```
/*
  Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; font-src 'self'; img-src 'self' data: https://tile.openstreetmap.org; connect-src 'self'; object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'
  Strict-Transport-Security: max-age=31536000; includeSubDomains
  X-Content-Type-Options: nosniff
  Referrer-Policy: strict-origin-when-cross-origin
  Permissions-Policy: geolocation=(), camera=(), microphone=(), payment=()
```

`'unsafe-inline'` для стилей нужен из-за инлайновых правил, которые скрипт
ставит на элементы (позиции существ, цвет фона, высота панелей). Для
скриптов `'unsafe-inline'` не разрешён — инлайновых `<script>` в проекте нет.

Ни один сайт не бывает «невозможно взломать». Что остаётся на вашей стороне:
включить HTTPS, держать секреты в панели хостинга, настроить резервное
копирование и обновлять всё, что появится вокруг проекта (сервер, CMS,
платёжный модуль).

## Доступность

- Клавиатурная навигация по всем интерактивным элементам, видимый фокус
  на любом фоне, ссылка «Перейти к содержимому».
- `aria-expanded` и `aria-controls` на аккордеонах и раскрывающихся
  карточках; свёрнутая панель скрыта и от скринридера, а не только визуально.
- Три состояния загруженности календаря различимы не только цветом: у каждого
  своя форма индикатора, у «нет мест» ещё и зачёркивание, а в `aria-label`
  дня состояние написано словами.
- Контраст текста ≥ 4.5:1 на всей глубине. На светлом участке погружения
  под текстом лежит мягкое затемнение, а приборная шкала переключается
  на тёмные чернила — без этого белый текст на бирюзовой воде проседал
  до 2.3:1.
- `prefers-reduced-motion: reduce` выключает движение полностью: сцена с
  частицами и фонарём убирается, фон становится статичным градиентом,
  прелоадер и переход между страницами не запускаются. Содержание остаётся
  на месте — страница не пустеет.
- Ничего не мигает чаще трёх раз в секунду.

## Производительность

- Ноль внешних библиотек. Из растровой графики — только шесть силуэтов
  существ, 166 КБ на все, и грузятся они по мере погружения; остальное — SVG и CSS.
  Вес страницы без сжатия: ~90 КБ логики, ~62 КБ стилей и ~68 КБ словарей.
  Заметная часть этого — подробные комментарии на русском (в UTF-8 кириллица
  занимает вдвое больше байт латиницы); при выкладке имеет смысл прогнать
  минификацию, и на сервере обязательно включить gzip или brotli.
- Все три словаря грузятся на каждой странице — так переключение языка
  происходит мгновенно, без перезагрузки. Если важнее первый байт, чем
  мгновенный переключатель, словари можно грузить по требованию.
- Один `requestAnimationFrame` на страницу, один слушатель скролла, один
  слушатель мыши. В самих обработчиках только флаг — вся работа в кадре.
- Анимируются только `transform` и `opacity`.
- Частицы на canvas, число зависит от ширины экрана; на телефоне их вдвое
  меньше, а курсор-фонарь и 3D-наклон карточек выключаются совсем.
- Цикл останавливается, когда вкладка скрыта.
- Прелоадер живёт не дольше 600 мс и снимается по таймеру при любой ошибке.

## Что осталось непроверенным

Честно, чтобы не было сюрпризов:

1. **`prefers-reduced-motion` в реальной системе.** Проверены CSS-правила
   и логика, но переключатель Windows «Показывать анимацию» при тестах не
   трогался. Проверьте: Параметры → Специальные возможности → Визуальные
   эффекты → Эффекты анимации → выключить, затем перезагрузить страницу.
2. **60 fps на среднем ноутбуке.** Нужен профиль во вкладке Performance
